# rules_swift_package_manager: local package not found when Package.swift is in another repository

`swift_deps.from_package` reads `Package.swift` from `@spm`, a repository generated by
`generated_package.bzl`. That manifest depends on a local package at `greeting`, next to it in
the same repository.

Since 1.22.0 the local package path is stored relative to the root of `@spm`, but
`local_swift_package` resolves it against the main repository.

## Running

```sh
./run.sh
```

With rules_swift_package_manager 1.26.0 from BCR:

```
Error in watch_tree: can't call watch_tree() on non-directory /path/to/local_package_external_manifest/greeting
```

With 1.21.0 (change the version in `MODULE.bazel`), or with a fixed local checkout
(`./run.sh /path/to/rules_swift_package_manager`), it prints
`local packages from another repository are found`.

Checked with Bazel 9.3.3, Xcode 26.2, macOS 15.7.
