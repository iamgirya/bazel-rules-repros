# rules_apple: dynamic frameworks with the same bundle name conflict in one package

`BUILD.bazel` builds the same framework for two flavors. Both are `App.framework`, so
both set `bundle_name = "App"`. Each `ios_framework` declares
`frameworks/App.framework/App` in the package for linking, and the two targets cannot be
built together.

## Running

```sh
./run.sh
```

With rules_apple 5.4.0 from BCR:

```
ERROR: file 'frameworks/App.framework/App' is generated by these conflicting actions:
Label: //:app_framework_paid, //:app_framework_free
```

To try a local checkout instead of the release:

```sh
./run.sh /path/to/rules_apple
```

With a directory per target both frameworks build.

Checked with Bazel 9.3.3, Xcode 26.2, macOS 15.7.
